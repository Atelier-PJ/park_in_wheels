# 테스트 방법

## JDK 17만 있는 환경

```bash
bash scripts/test-core.sh
```

Gradle 환경에서는 `gradle :core:check`로 동일한 시나리오를 실행한다. 실제 테스트는 `scenarioTest` 태스크에 포함되어 있으며, 일반 JUnit 테스트 수와 혼동하지 않는다.

UNKNOWN에서 시작 차단, 제한 즉시 일시정지, 제한 중 재개/부화 차단, 제한 해제 후 수동 재개, 5km 미만 부화 차단, 중복 부화·반복 이벤트, 새 탐험 초기화, 프로세스 복원 후 차단, 앱 종료 중 이동 거리 반영, 미지원·NaN·역행 거리, 저장 오류 중 제한 적용을 검증한다.

## demoDebug APK 수동 시나리오

1. 앱을 실행한다. 모의 데이터 표시와 초기 차단 화면을 확인한다.
2. `주차·이용 가능 가정` → `새 탐험 시작`을 선택한다.
3. `주행·이용 제한 가정`을 누른다. 탐험 화면과 버튼이 숨겨지는지 확인한다.
4. 제한 상태에서 `모의 누적 거리 +1 km`를 다섯 번 누른다.
5. `주차·이용 가능 가정`으로 변경한다. 자동 부화·자동 재개가 없어야 한다.
6. `보호자 확인 · 이어하기` → `공룡 알 부화하기`를 누른다. 카드가 한 장 증가해야 한다.
7. 화면 회전·홈 이동·강제 종료·재실행 후 카드와 여정 기록이 보존되는지 확인한다. 홈 복귀/재실행 시 초기 차단이 적용되어야 한다.
8. 활성 탐험에서 `거리 미지원 가정`을 선택한다. 부화가 차단되는지 확인한다. +1 km로 다시 유효 값을 전달한다.
9. `연결 끊김 가정`을 선택한다. 게임 UI가 숨겨져야 한다.

실제 Pleos 호출, Android 화면/터치, 에뮬레이터 동작은 도메인 테스트로 검증되지 않는다. 수동 시나리오와 실제 API 체크리스트 결과를 따로 남긴다.

## pleosDebug 런타임 시나리오

`PLEOS_CONNECTION.md`의 AVD 절차를 수행합니다. `pleosDebug`에는 모의 패널이 없어 모든 제한·거리 이벤트는 실제 플랫폼/SDK에서 받아야 합니다. 도메인 테스트·lint·APK 빌드 결과와 런타임 결과를 구분하세요.
